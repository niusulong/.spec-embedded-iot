# spec-knowledge-archiver 功能说明

> 嵌入式 IoT 知识库的**归档 + LLM-Wiki 渐进加载**工具。把项目 `.spec/` 下的分析与方案文档归档到跨项目持久化知识库的 raw 区（原文保真），并输出 wiki 维护提示词，供 agent 按 `INDEX.md → entries → raw` 三段渐进加载检索。

## 一、定位

| 维度 | 说明 |
|------|------|
| 输入 | 项目 `.spec/{bug,requirement}/` 下的 markdown 文档（可多文件） |
| 输出 | 持久化知识库 `~/.spec-embedded-iot/knowledge/raw/platform/{平台}/{类型}/`：`.archive_meta.json`（元数据）+ `index.md`（人类可读索引）+ `*.md`（归档原文）；并输出 wiki 维护提示词 |
| 跨项目 | 知识库独立于任何代码仓库，按芯片平台隔离（EC626 / ASR1603 / N58 / UIS8850 / UIS8852 / QCX216 …） |
| 配置驱动 | 新增知识类型通常只需在 `knowledge_config.json` 加一条配置 |
| 检索范式 | LLM-Wiki 渐进加载（无向量库、无 CLI 语义检索）：agent 读 `wiki/INDEX.md` → `wiki/entries/*.md` → 回溯 `raw/` 原文 |

## 二、数据流

```
归档链路                                    wiki 维护                              检索链路（agent 渐进加载）
.spec/{bug,requirement}/    →   knowledge/raw/platform/{平台}/{dest}/   →   wiki/INDEX.md
  Bug分析.md / 需求.md            .archive_meta.json (元数据)                全部条目轻量目录（定位）
  方案.md / 任务.md (多文件)      index.md (人类可读表)                      │
       │                          *.md (归档原文，保真拷贝)                  ↓
  kb.py archive                  │                                       wiki/entries/*.md
  - 合并多文件(主文档优先)       agent 按 kb.py wiki guide                  单条目精炼页（细节）
  - 注入 工作项ID/项目ID=NA      的提示词维护 entries/concepts                │
  - hash 增量跳过                                                            ↓
  - 原子写 + meta/index 重建                                                raw/platform/{平台}/{dest}/...
                                                                            原文回溯（保真全文）
```

归档后**自动输出 wiki 维护提示词**给 agent（可用 `--no-wiki-prompt` 跳过）；agent 据此生成/更新 `wiki/entries/*.md`，由 `kb.py wiki lint` / `kb.py wiki status` 校验覆盖率。

## 三、脚本职责（`skills/spec-knowledge-archiver/scripts/`）

| 脚本 | 职责 | 关键函数/说明 |
|------|------|----------|
| `kb.py` | **统一入口**（LLM-Wiki 路线）：子命令 `archive`（归档到 raw 区）/ `verify`（raw 区完整性校验）/ `wiki lint\|status\|guide`（wiki 维护）/ `status`（知识库总览）。转发到 `wiki/archiver.py`、`wiki/lint.py` 等 | `archive`、`verify`、`wiki`、`status` 子命令 |
| `knowledge_archiver.py` | 旧版归档主程序（被 `kb.py archive` 内部复用）：多文件合并、hash 增量、字段注入、meta/index 重建 | `archive_entry`、`merge_md_files`、`generate_index` |
| `extract_summary.py` | 从 markdown 提取结构化摘要（解析摘要节表格 → 全文兜底 → 首段兜底） | `_parse_table_rows`、`_find_summary_section`、`extract_summary` |
| `wiki/` | wiki 维护子包：归档器（`archiver.py`）、分块（`chunker.py`）、frontmatter（`frontmatter.py`）、一致性检查（`lint.py`）、维护指南（`guide.py`）、引用解析（`references.py`）、日志（`log_writer.py`） | `cmd_archive`、`GUIDE_TEXT` |
| `common.py` | 共享：路径常量、配置加载、平台推断、路径/文件名工具、摘要文本构建、markdown 分块、原子 IO | `load_config`、`infer_platform`、`build_summary_text`、`safe_filename` |

> 注：旧的 `embed_indexer.py`（向量索引构建）与 `embed_search.py`（CLI 语义检索）已在 LLM-Wiki 重构中删除，不再存在。

## 四、配置 Schema（`~/.spec-embedded-iot/knowledge/knowledge_config.json`）

配置核心是 `doc_types`（归档用）：

### `doc_types`（归档脚本用）
```jsonc
"bug": {
  "source_dir": "bug",              // 项目 .spec/ 下的源目录
  "dest_dir": "bug-solutions",      // raw 区目标目录名
  "index_columns": { ... },         // index.md 表格列
  "summary_section": "结构化摘要",  // 摘要节标题
  "summary_fields": { ... },        // 摘要字段映射（中文 label → 英文 key）
  "list_fields": ["symptoms", "keywords"],
  "max_field_lengths": { "root_cause": 60 }
}
```

> 注：配置文件中可能仍保留 `collections` 段，这是旧向量索引路线（ChromaDB）的遗留配置，LLM-Wiki 路线下不再使用，检索完全由 agent 渐进加载完成，无需向量索引构建。

## 五、命令清单

统一入口为 `kb.py`（`skills/spec-knowledge-archiver/scripts/kb.py`）。

### 归档（`kb.py archive`）
```bash
python scripts/kb.py archive --project {项目路径} --type bug --all          # 批量归档
python scripts/kb.py archive --project {项目路径} --type all --incremental   # 增量归档所有类型
python scripts/kb.py archive --project {项目路径} --type bug --name "COAP"   # 指定条目（部分匹配）
python scripts/kb.py archive --project {项目路径} --platform EC626 --type bug --all  # 手动指定平台
python scripts/kb.py archive --project {项目路径} --type bug --all --no-wiki-prompt      # 跳过 wiki 维护提示词
```

### 校验（`kb.py verify`）
```bash
python scripts/kb.py verify --project {项目路径} --type bug                  # raw 区完整性校验
```

### wiki 维护（`kb.py wiki`）
```bash
python scripts/kb.py wiki lint                # 检查 wiki 一致性（断链、孤儿、元数据缺失等）
python scripts/kb.py wiki status              # wiki 覆盖率统计
python scripts/kb.py wiki guide               # 打印完整 wiki 维护指南（给 agent 用）
```

### 知识库状态（`kb.py status`）
```bash
python scripts/kb.py status                   # 知识库总览（raw 区 + wiki 覆盖）
```

### 检索（agent 渐进加载，无 CLI 命令）
检索不再通过 CLI 命令，而是 agent 三段渐进加载：

1. 读 `knowledge/wiki/INDEX.md` 全局目录定位相关条目；
2. 读 `knowledge/wiki/entries/*.md` 精炼页取细节；
3. 必要时回溯 `knowledge/raw/platform/{平台}/{类型}/...` 原文（保真全文）。

## 六、知识库目录布局

```
~/.spec-embedded-iot/knowledge/
├── knowledge_config.json                 [运行时配置]
├── raw/                                  [源数据：归档原文保真 + meta]
│   └── platform/{平台}/
│       ├── bug-solutions/                .archive_meta.json + index.md + *.md
│       ├── requirement-solutions/        同上
│       ├── code-summary/{模块}/代码总结.md
│       ├── official-docs-md/
│       └── 项目概览.md
├── wiki/                                 [全局 wiki：渐进加载入口]
│   ├── INDEX.md                          全部条目轻量目录
│   ├── entries/*.md                      单条目精炼页
│   └── concepts/*.md                     概念页
└── protocols/                            [协议官方资料]
```

平台名从项目路径推断（`D:\EC626\` → `EC626`），也可 `--platform` 手动指定。

## 七、关键设计约定

1. **工作项ID/项目ID 追溯**：所有归档文档的摘要须含 工作项ID（bug）/ 项目ID（requirement），缺失时自动注入 `NA`。
2. **主文档置顶合并**：多文件归档时，含「结构化摘要」节的文档置顶，section 间用 `\n\n---\n\n` 连接。
3. **hash 增量**：基于源文件二进制算 hash，内容+文件名都未变则跳过；注入的 NA 行不进 hash（避免死循环重写）。
4. **原子写 + 写新再删旧**：迁移时先 atomic_write 新文件再删旧文件，防数据丢失。
5. **隐式约定**：`doc_type.dest_dir` 即 raw 区的目标目录名（`raw/platform/{平台}/{dest_dir}/`），也是 wiki 条目按类型分组的依据。
