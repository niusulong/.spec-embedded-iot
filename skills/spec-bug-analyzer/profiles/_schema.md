# Profile Schema —— 平台分析方法契约

> 本文件定义 `profiles/{平台}.md` 的结构契约。写/改任何 profile 必须遵循；`scripts/check_profile.py` 据此校验。
> 与 `knowledge/schema.md` 的边界：那份管**知识库**（raw/wiki/案例），本份管**技能仓内的平台分析方法**。两者不重叠。

## 设计原则

profile 是**平台相对通用基线的"差异补丁"**，不是该平台分析方法的完整手册。通用的不抄进来，只补不同。违反"只保留差异"即违反 DRY，会让 profile 臃肿、增加模型理解负担。

## 通用基线（profile 禁止重复）

以下内容已在通用层，profile 里再出现即违规（`check_profile.py` 会警告）：

| 通用基线 | 现位置 |
|---------|--------|
| 8 步分析流程、核心原则、证据标注 `[事实:文件:行号]/[推断]/[待验证]`、反驳自检闸、证据不足即熔断 | `SKILL.md` |
| 通用问题模式 8 类（缓冲区溢出/超时/参数错误/状态机异常/资源耗尽/TLS/AT错误/断连重连） | `references/analysis-patterns.md` 通用段 |
| 通用分析手法（时间戳间隔统计 / count 驱动批量识别 / 多复现点逐拍对比 / 报文字节验证 / 枚举重构回归定位） | `references/analysis-patterns.md` 手法段 |
| log/pcap 脚本用法、对比分析方法、报告模板 | `references/*` |

## 六段结构

每个 profile 用以下六段。**只有「代码地图」必填**，其余"无差异则整段省略"——多数平台 profile 因此很薄。

| 段标题 | 内容 | 差异约束 | 必填 |
|--------|------|---------|------|
| `## 根注解` | 架构/RTOS/工具链，1-2 行 | **仅当它解释了下面的差异时才写**。不解释差异就别写 | 否 |
| `## 日志差异` | 时间戳格式 / tag 约定 / 默认可见性 | **只列与通用假设不同的**；相同则整段省 | 否 |
| `## 代码地图` | 子仓结构 + 关键模块路径锚点 | 天然平台特异，是"怎么在本平台找代码"的依据 | **是** |
| `## 检索清单` | 平台特有/高频关键串与错误码 | **通用串黑名单禁止**（见下）；只列平台独有 | 否 |
| `## 差异化定位手法` | 本平台独有的诊断手法 | **通用手法禁止抄**；只列平台独有 | 否 |
| `## 平台专属问题模式` | 本平台常踩的坑（现象-日志特征-根因方向） | **通用 8 模式禁止重复**；只列本平台特有 | 否 |

### 检索清单通用串黑名单（check_profile 据此扫）

检索清单段禁止出现以下通用串（出现即警告——它们属于通用基线，列在这里是重复）：

```
ERROR | error | fail | Fail | timeout | Timeout | overflow | PARAM_ERROR
| INVALID_PARAM | disconn | closed | reconnect | 断连 | 重连 | 超时
```

> 平台独有的、带平台前缀的串不算违规（如 `memp_malloc`、`dlmalloc`、`DataAbort`、`g_osAssert`）。

## 一致性约束（三名一致）

```
profile 文件名  ==  knowledge/raw/platform/{平台}/ 目录名  ==  SKILL.md 仓库名映射输出的平台名
```

- 平台命名规则遵循单一真理源：`skills/spec-knowledge-archiver/references/section0-spec.md` §一（纯平台名，禁止架构后缀/括号/版本号）。
- 当前已纳管的平台：`EC626` / `ASR1603` / `UIS8850` / `UIS8852` / `QCX216` / `RDA_UIS8910DM_RLS`。
- `check_profile.py` 校验：每个 `profiles/{X}.md` 的 `X` 必须对应 `knowledge/raw/platform/{X}/` 已有目录（防止"profile 叫 UIS8852、知识库目录叫 8852"错位导致回溯落空）。

## 空框架规范

某平台暂无专属积累时，**保留框架、不强造内容**：

- `## 根注解` 填确定的架构事实（如"RISC-V RV32 + RT-Thread"）。
- `## 代码地图` 即使无积累也保留段，内容写 `> 暂无积累，待实战补充。定位时参考该项目的 项目概览.md §2 目录结构。`
- 其余段如无积累，整段省略（不写空标题）。
- profile 末尾可加一行 `> 本平台暂无专属分析方法积累，分析时以通用基线为准。`

这样探测命中时 agent 明确知道"该平台无专属积累、走通用基线"，优于"无 profile 退化"。

## 写作纪律

1. **先问"这和通用基线不同吗"**——相同就不写。
2. **代码地图给锚点，不给全路径树**（全路径树是 `项目概览.md` 的职责，不重复）。
3. **每条都有依据**——从实战分析或确定的平台事实提炼，不臆造。没依据就留空框架。
4. dump 分析方法（PC/LR/SP 解析、堆栈遍历、反汇编）**不属于本技能**，不写进 profile——那是 dump 分析技能的职责。
