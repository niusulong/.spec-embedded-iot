# 常见问题模式

> 用于 Step 4 根因定位时快速对号入座。模式只是方向提示，定位后仍需 Step 5 代码交叉验证，不要把模式当结论。

## 通用模式

| 问题模式 | 关键日志特征 | 根因方向 |
|----------|--------------|----------|
| **缓冲区溢出/不足** | `BUFFER_TOO_SMALL`、`overflow`、`EXCEED`、`truncated` | 缓冲区配置过小 / 越界写 |
| **超时问题** | `TIMEOUT`、`timeout`、长时间无响应后断开 | 网络状态差 / 任务阻塞 / 超时配置过短 |
| **参数错误** | `PARAM_ERROR`、`INVALID_PARAM`、`illegal`、`bad value` | 输入校验缺失 / 协议理解偏差 / 单位换算 |
| **状态机异常** | `state` 跳转异常、状态不一致、重复进入某态 | 逻辑错误 / 并发竞争 / 事件丢失 |
| **资源耗尽** | `EXHAUST`、`NO_MEMORY`、`NO_HANDLE`、`alloc fail` | 资源泄漏 / 未释放 / 配置上限过低 |
| **TLS/SSL 失败** | `handshake`、`alert`、`certificate`、`-0x7xxx` 错误码 | 证书 / 加密套件 / 版本兼容 / 系统时间未同步 |
| **AT 命令错误** | `ERROR`、`CME ERROR`、`CMS ERROR` | 命令格式 / 参数越界 / 模块状态不满足前置 |
| **断连/重连** | `disconn`、`closed`、`reconnect`、链路状态回落 | 心跳超时 / 对端主动关闭 / 底层链路掉线 |

## 通用分析手法（跨平台验证有效）

> 以下手法在实际 bug 分析中被用户认可、跨平台可复用，定位到根因方向时优先采用。

| 手法 | 适用场景 | 操作要点 |
|------|----------|----------|
| **时间戳间隔统计（gap analysis）** | 概率性失败、超时类问题 | 提取同一事件（如 `TCPSEND channel=`）的所有时间戳，算间隔分布（中位数/p95/异常长间隔）；异常长间隔若与外部超时点（如 PC 端 5s 超时）精确吻合，即把"概率性失败"量化为确定性证据 |
| **多异常点逐拍对比** | 有 ≥2 个复现点 | 把多个复现点的状态机/报文逐拍列表对比（TCP连接→横幅→认证→静默时长→错误码）；相同节律 = 同一根因，不同节律 = 分属不同问题 |
| **count 驱动的批量模式识别** | 压测/长稳/概率性、同一报错多次出现 | 先 `grep -c` 各候选错误标志（如各类 ERROR / 各阶段 timeout / 失败码），用**数量分布**判主模式与异类——例如「15 次 ERROR 但只 2 次 exec timeout」立即说明非同一原因、必须分类。这是批量问题的第一步，比逐条翻日志快一个量级，也避免把少数异类错归为多数模式 |
| **抓包/原始报文验证** | 应用层假设（超时/keepalive/服务端主动关闭） | 抓包解码后，应用层回码（如 FTP 的 421/426）必须在报文字节里找到证据，找不到即排除应用层超时；TCP RST vs 应用层关闭需靠报文区分，不能靠 AT 日志猜。具体解析方法见 `pcap-analyzer-guide.md`，原始 .pcap 用内嵌 TShark2MCP MCP server（封装 tshark，替代 Wireshark），不要现场手写 struct 解析 |
| **枚举重构回归定位** | 升级后行为翻转的回归 | `git diff -w`（忽略 CRLF）看魔法数字→枚举的重构，对照老代码语义值 vs 新枚举默认值（如 `regFlag==1` → `regFlag==AUTO_REG`，若 `AUTO_REG=0` 则语义翻转）；再用 `git log -S "枚举名"` pickaxe 锁定引入提交 |

> 平台专属手法（如 EC626 的 heap 失败点三数字判别）见 `profiles/{平台}.md`。

## 搜索技巧

- **先定位报错时刻**：用 `stats` 看错误关键字的时间分布，锁定首次出现的时间点，再用 `search` 带上下文查看。
- **沿时序向上追溯**：报错点向上找前一条相关日志（请求/事件），逐条回溯触发源，不要只盯报错那一行。
- **对比基准**：正常/异常日志都有时，先用 `compare` 自动 diff，人眼聚焦差异点（见 `contrast-analysis-guide.md`）。
- **错误码先查定义**：报错码（如 `-0x7200`）先查对应头文件/枚举定义再推理含义，不要猜。
- **关注资源趋势**：内存/handle/句柄类问题，对比问题发生前后占用趋势，判断是泄漏还是突发耗尽。
